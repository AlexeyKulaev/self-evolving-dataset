# Итог реализации — 29 октября 2026

Реализован запускаемый Python-пайплайн с семантическим исполнителем через
`codex exec` и численным обучением отдельной модели-ученика. Это реализация
алгоритма и его проверка на малых примерах; реальный пользовательский бенчмарк
и содержимое `goal.md` / `architecture.md` ещё не предоставлены.

## Что реализовано

- Чтение и полная подстановка `goal.md` и `architecture.md` во все семантические
  промпты. Строгая фиксация конфигурации/контекста и исходных данных для resume.
- ChatGPT создаёт домены по одному концепту/правилу, распределяет весь исходный
  датасет по доменам, при необходимости дополняет каталог и один раз сортирует его.
- ChatGPT генерирует примеры с ответами в исходной JSON-схеме, без целевого C и
  намеренного усложнения. Отдельный запрос проверяет правильность генерации.
- Неизменный validation-набор от ChatGPT, semantic judging ответов ученика;
  тестовые данные доступны только отдельной команде после завершения обучения.
- Полный цикл stage training → loss/accuracy → веса → удаление освоенных →
  переходы доменов → пополнение/пересчёт C → новое окно и случайные батчи.
- 50% N делятся всеми новыми доменами; восстановление добавляет до 20% N.
  Проверки забывания выполняются после каждого этапа. Завершение — все домены
  имеют статус passed, включая завершённое восстановление.
- Immutable checkpoints ученика и scheduler, atomic pointer на последний
  завершённый этап, RNG, кэш семантических операций, возобновление после ошибок.
- Baseline с теми же стартовыми весами и числом предъявлений; отдельный test
  evaluator; отчёт запуска с метриками и всеми временными решениями.
- Численные backend: обучаемый NumPy RNN; Hugging Face causal-LM SFT; протокол
  Student для другой архитектуры/алгоритма. Public CI не использует подписку.

## Проверки

27 автоматических тестов прошли в Python 3.12.3. Среди них:

- формула C против явного попарного расчёта; независимость C от ответа;
- численный finite-difference контроль градиентов RNN, снижение loss;
- настоящий локальный маленький GPT-2 через адаптер HF, без скачанных весов;
- сохранение/восстановление optimizer и dropout RNG с идентичным следующим шагом;
- пример весов из исходной схемы, совместные 50% новых доменов, край окна,
  предел replay, paired delta;
- полный сценарий exit → два сигнала забывания → replay → восстановление;
- эквивалентность resume непрерывному запуску и откат незавершённого этапа;
- фиксированный validation, конфликтующие/дублирующиеся примеры, отделение test;
- JSON-формат, контекст из файлов и параметры `codex exec`, отказ от API-key
  authentication и отказ от незаметного игнорирования Fast.

Версии численного тестового окружения: PyTorch 2.15.0+cpu, Transformers 4.57.6,
NumPy 2.5.4. NumPy-only demo также проверен с bundled runtime.

Offline demo прошёл 4 этапа: 48 предъявлений ученику и 48 предъявлений baseline.
Обе модели получили accuracy 0/3 на отдельном микротесте. Это ожидаемо слабый
короткий запуск случайно инициализированной модели, а не результат о качестве
метода. Домен может завершиться по плато при нулевой точности.

## Проверка подписки и CLI

Изначальный локальный Codex CLI 0.153.4 не распознал метаданные `gpt-6.1-sol`,
сообщил об игнорировании Fast и получил серверную ошибку недоступной модели.
Установлена отдельная локальная копия CLI 0.165.0; глобальная установка не менялась.
Через новую копию успешно выполнены генерация двух примеров и отдельная
семантическая проверка с точными параметрами `gpt-6.1-sol / xhigh / fast`.

Затем завершён полный live smoke через `examples/codex-smoke/config.toml`:
один домен, 20 примеров в пуле, 2 фиксированных validation-примера, 2 этапа,
4 обучающих предъявления. Успешно выполнены 11 уникальных семантических запросов:
создание доменов, классификация seed, упорядочивание, генерация validation и train,
две проверки генерации и четыре проверки ответов ученика. Финальная validation
accuracy — 1/2; выход по плато. Все этапы и checkpoint завершены, ошибки доступа
к заданной модели и пропуска Fast в этом запуске не наблюдались. Этот маленький
тест подтверждает интеграцию, а не обучающую эффективность.

В проекте бинарник лежит в игнорируемом `.tools/codex`. Для клона репозитория
инструкция установки находится в README. Конфигурация не переключает модель,
режим или способ оплаты при ошибке. `doctor --live` позволяет повторить проверку.

## Что нужно перед реальным экспериментом

Заполнить два пользовательских Markdown-файла, предоставить исходный JSON/JSONL,
указать поля вопроса/таблицы и ответа и выбрать численный backend ученика.
Текст `architecture.md` используется в промптах; произвольная архитектура из
свободного текста не компилируется автоматически. Если готового HF SFT backend
недостаточно, реализуется адаптер Student, а scheduler остаётся тем же.

Публикуются код, документация и созданные для тестов примеры. Рабочие данные,
логи, авторизация и checkpoints не входят в Git.

## Вопросы, оставленные для следующей итерации

1. **Пункт 6:** оправдана ли стоимость проверки всего пула после каждого этапа,
   или проверять только предъявленные примеры/выборку? Сейчас выбран весь пул,
   архив сохраняется и используется при забывании.
2. **Пункт 7:** считать ли плато на низкой точности окончательным прохождением
   или возвращаться к домену позже? Сейчас выход окончательный, кроме обычного
   механизма забывания; причина `plateau` явно сохранена.
3. Нужна ли иная формула delta, проверка смысловых дубликатов, независимый
   верификатор эталонов или более строгая схема равномерной генерации?
4. Для исследовательского сравнения: оставить общий итоговый банк кандидатов
   baseline или реализовать независимый online baseline? Сравнивать ли также
   вычислительные затраты, токены и затраты семантического исполнителя?

Все эти пункты имеют исполняемые значения по умолчанию и не блокируют запуск.

## Источники технических контрактов

- [GAIN-RL](https://arxiv.org/abs/2506.02281): исходный источник углового сигнала;
  наша формула намеренно не разделяет токены на части.
- [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode):
  `exec`, structured output, output-last-message, ephemeral и ChatGPT login.
- [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference):
  model_reasoning_effort и service_tier.


## Полный список принятых допущений

- **Пункт 6 — проверка освоенности.** После этапа проверяется весь пул каждого
  активного или восстанавливаемого домена. Два правильных ответа на соседних
  этапах удаляют пример из рабочего пула, но сохраняют в архиве. При забывании
  архивные примеры первыми возвращаются в пул (до 2N), их счётчики сбрасываются.
  Это временный выбор; цена — до 2Nk ответов и семантических проверок на этап.
- **Пункт 7 — плато.** Два прироста accuracy ниже соответствующего delta выводят
  домен даже при низкой точности. Причина `plateau` записывается отдельно от
  `accuracy`. Позднейшего повторного прохождения без обнаруженного забывания нет.
  Выход всех доменов не означает, что модель достигла целевой точности.
- **C.** Среднее косинусное сходство всех различных пар последних скрытых
  векторов только вопроса/таблицы. Ответ, goal.md, architecture.md, служебный
  префикс, padding и специальные токены исключены. Самосходства не включены;
  для одного токена C=0. Это модификация GAIN-RL, а не буквальное воспроизведение.
- **Равномерная генерация.** Генератор не получает целевой C, ошибки ученика
  или запрос на усложнение. Просим равномерное разнообразие внутри правила;
  строгую равномерность по пространству естественного языка это не гарантирует.
- **Проверки и delta.** Validation создаётся ChatGPT один раз. По умолчанию
  генерация проверяется отдельным вызовом того же ChatGPT. Delta — максимум
  заданного минимума и двух стандартных ошибок парных разностей бинарных
  результатов; можно установить фиксированный delta. Это эвристика, не
  гарантия контроля ложных срабатываний при многократных проверках.
- **Граничные случаи.** Новые домены вместе делят floor(N/2), оставшаяся доля
  идёт старым. Если старых не осталось, новые делят весь N. При старте доли
  равные. Целочисленные квоты распределяются методом наибольших остатков.
- **Повторы и забывание.** Батчи случайны с возвращением из stage dataset.
  Восстанавливаемые домены добавляют 10–20% N сверх основного набора; число
  шагов и размер батча не меняются. Поэтому их примеры конкурируют за тот же
  бюджет предъявлений. Завершение — все статусы passed, включая возвратившиеся.
- **Порядок служебных операций.** После измерений проверяем освоенность и
  переходы доменов; пополнение и пересчёт C выполняются для доменов следующего
  этапа. Новые домены получают начальную валидацию до отбора окна. Так нет
  устаревшего C у восстановленных доменов и лишнего пополнения уже выведенных.
- **Baseline.** Все домены смешиваются с равными вероятностями, без окон,
  весов и смены доменов. Кандидаты — общий банк всех обучающих примеров,
  полученных в завершённом адаптивном запуске, включая архив. Стартовые веса
  и число предъявлений совпадают. Это offline comparator с доступом к итоговому
  банку; независимая online-генерация baseline пока не реализована.
- **Ограничения.** Точное совпадение входов между split запрещено, но
  семантические парафразы автоматически не исключаются. Проверка тем же
  учителем не гарантирует истинности эталонов. Поддержан JSON/JSONL с общей
  схемой; таблицы могут быть строками или вложенными JSON-массивами/объектами.
  Картинки таблиц требуют отдельного адаптера. Метрики test не участвуют в цикле.
- **Архитектура.** Markdown-файлы целиком входят в каждый семантический промпт.
  Численный backend выбирается явно в TOML: готовый causal-LM SFT, демонстрационный
  NumPy RNN или Python plugin. Произвольное описание архитектуры в Markdown
  само по себе не преобразуется в исполняемую нейросеть; для другого метода
  обучения нужен адаптер Student. Демонстрация не является проверкой SOTA.
